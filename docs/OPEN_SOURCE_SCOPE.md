# 开源范围与使用边界

本项目把小米 AI 音箱 S12A 改造实验中的 Linux 客户端、面板适配和构建工具
整理为可审查的源码。目标是连接用户选择的小智 WebSocket 服务，不依赖开发者
自己的云平台、账号系统或发布服务器。服务端仍负责语音识别、大模型和语音合成；
这些能力是否可用取决于所连接的小智服务及其配置。

## 包含什么

- 音频采集与播放、小智协议客户端和本地面板适配源码。
- 麦克风通道选择及与现有原厂音频库的接口适配。
- 可重复生成的原创短提示音，不含原厂录音和历史 TTS 缓存。
- 配置示例、构建工具和不连接真实设备的测试。

## 不包含什么

- 原厂固件镜像、Linux 内核、设备树、引导程序、原厂根文件系统。
- 原厂唤醒库、声学模型、波束形成算法实现和原厂提示音。
- 任何人的 Wi-Fi 密码、设备令牌、签名私钥、录音或云服务 API Key。
- 已经验证适用于所有 S12 硬件修订的通用刷机包。

**公开源码不等于整套原厂固件已开源。** 原厂组件由用户从自己的音箱或合法
取得的原厂固件中提供。构建目录、提取产物、个人配置和最终镜像均应留在本地，
不提交版本库。这里的 MIT 许可证不授予原厂组件的再分发权。

## 离线唤醒和多麦克风

离线“小爱同学”唤醒使用音箱原有唤醒库及模型，并通过公开在此的接口适配层
调用。模型本身没有重新实现，也不随仓库分发。原有六麦克风采集及声学处理
可被客户端使用；硬件兼容、库版本及声学校准会影响实际效果。若原厂组件缺失
或不匹配，应拒绝启用相关功能，不静默宣称拥有离线识别能力。

语音识别、自由文本对话和动态 TTS 通常仍需要所配置的小智服务。这些不能与
本地的固定唤醒词检测、短提示音混为一谈。

## 已知限制和验证状态

历史设备实验已经验证过基础收音、播音、面板和本地唤醒；**这次整理后的通用
构建尚未在真实音箱上重新验收**。通过离线编译或模拟协议测试不代表已通过
真机声学测试，也不代表可直接替代可靠的原厂家用体验。

- 很轻、很短的词句仍可能漏收；不能承诺任意距离、音量下准确识别。
- 播放时的唤醒打断依赖收音、回声抑制和服务端协作，仍可能漏打断或误触发。
- 连续对话中的家人闲聊可能被当成回复；不含经验证的说话人身份绑定。
- 部分服务端扩展、音乐队列、主动播报和工具消息不属于基础小智协议；服务端
  不支持时不可假定存在。配置界面也不应因此伪装成支持这些能力。
- 断网、云端错误及服务超时仍可能影响回答。离线唤醒成功不等于联网对话成功。

## 保留可恢复性

初次验证应使用可回滚的内存试运行，并保留自己的启动环境和可用原厂分区。
本仓库的公开准备工作不会自动操作用户的音箱；当前家用设备可继续运行原厂
系统。任何正式刷写都应先核对型号、镜像、分区及实际回读结果，不把另一位用户
的设备身份、升级凭据或备份当作自己的恢复方案。
