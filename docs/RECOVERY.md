# 安装与恢复边界

本首版没有一键刷机脚本。`build_image.py` 只生成本地候选镜像，不操作设备或串口。这样可以先审查、复现和做 RAM 启动测试，再单独评估持久安装。

候选也不包含向 NAND 环境写入“本次启动健康”的确认器。原厂启动失败计数策略可能让下一次重启自动切回其它槽，因此**不能把一次候选开机成功当作持久安装已完成**。正式安装还需要针对实际启动策略核对健康确认与回滚，不应靠删除失败保护来解决。

## 目标硬件

当前适配依据是第一代小米 AI 音箱 S12/S12A，原厂系统版本 1.76.54，ARM32 Linux。不能用于小爱 Mini、触屏款、其它代次，或 ESP32 开发板。

不同批次的分区、内核、声卡与引脚可能不同。实际安装前至少核对原厂镜像来源、当前分区表、备用槽名称、坏块状况、串口电平和原厂启动恢复方法。

## 建议顺序

1. 保存本机可读的完整启动环境、分区表、设备校准/密钥与固件备份；在能够验证的范围内核对读回。只有部分镜像备份不能称为完整可救砖备份。
2. 验证原厂 `boot0` 能正常启动，保留原厂 `system0`。记录恢复入口和需要的硬件。
3. 从用户自备原厂镜像构建候选，核对输出的内核、DTB 与原输入一致。
4. 使用针对本机已验证的 RAM 启动流程试运行，确认麦克风、扬声器、静音、触摸、灯光和服务连接。RAM 运行不等于完成持久安装。
5. 持久安装属于独立步骤，必须有仅面向备用槽、含整段读回与失败处理的目标适配工具。本仓库尚未提供面向任意用户主板的一键安装器。

**不要刷写整颗 NAND，不要覆盖 Bootloader、原厂 `boot0`、`system0`、密钥或校准区。** 不要把本地包中的 Wi-Fi、token、CA 配置或含这些内容的完整镜像上传到公开仓库。

## 切回原厂的原理

在已核对过启动策略的 S12A 上，`boot_part` 选择 `boot0` 或 `boot1`；`boot_failcnt` 会影响下一次启动是否自动切槽。恢复原厂需要同时检查这两个值、完整环境 CRC 与 `storeboot` 脚本，再通过原厂环境驱动或受控 U-Boot 流程处理。不要把网上的 `setenv` 示例不加核对地用于另一块主板。

修改启动环境后应完整读回确认，并观察真实原厂启动。原厂联网后查询到设备型号和原厂固件版本，只能证明系统和局域网接口已起来，语音、云服务和绑定仍需分别验收。硬件串口和完整备份是恢复手段，不是“任意失败都能救砖”的保证。

本项目不分发任何特定家庭音箱的环境快照、私有恢复凭据或改写环境工具。
