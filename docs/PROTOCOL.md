# 协议兼容范围

目标是小智 WebSocket **版本 1**，以 [上游协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md) 为依据。没有采用 MQTT，也不需要额外的项目作者控制连接。

## 数据路径

客户端向 `ws://127.0.0.1:18080/xiaozhi/v1/` 发起标准 Upgrade；桥验证本机令牌、设备身份和请求路径后连接用户指定的完整上游 URL。上游地址可以有自己的路径和查询参数，但请求方不能用入站路径或查询参数改选服务器。

握手使用 `Device-Id`、`Client-Id`、`Protocol-Version: 1`，以及上游配置的可选 `Authorization: Bearer ...`。上游令牌不写入源码；本机令牌不发给上游。HTTPS 证书验证保持开启；公开网络需要 `wss://`。明文 `ws://` 只允许显式的内网或回环 IP。

`hello` 宣告 Opus、16 kHz、单声道、60 ms 上行帧；有面板设备工具时宣告 MCP。下行按服务端协商的 Opus 采样率解码。二进制消息是原始 Opus 帧，不加入作者平台的包头。桥对成功 Upgrade 后的数据字节透明转发。

本地先完成一句话采集，再按音频帧时长发送，最后发标准 `listen/stop`。**没有启用流式 ASR**；也不再要求服务端实现自定义 `audio_packets` 队列屏障。此保守模式能减少普通服务端音频队列被 stop 抢先终止的差异，代价是上行发送仍有耗时，后续可单独优化并做兼容测试。

## 可选能力

- 标准 `tts`、`stt`、`abort` 和 MCP 消息保留。
- 持续聊天需服务端在回答完成后保留对话状态；不能仅凭一句话推断所有服务端都会进入下一轮收音。
- 为减少家庭闲聊被当成回复，候选启动脚本默认 `--followup-seconds 0`。若需要限时连续对话，可以在本地修改 `runtime/client_wake.sh` 为 `--followup-seconds 8` 后重新构建。没有扩展元信息的标准服务端仍可在回答后开启这一时间窗，但无法像支持该扩展的服务端一样精细区分“结束”和“等待回答”。
- 私有 `dialogue_state`、音乐队列、本地意图映射等扩展，即使客户端能识别，也不作为默认服务端的必备能力。
- 原先项目作者平台的常驻控制 WebSocket、主动播报队列、设备数据库注册、发布渠道和账号调用没有接入本仓库。
- 上游服务的激活或设备绑定由该服务决定。配置 WebSocket 地址和凭据不等于已经完成官方托管服务激活；本首版没有实现官方激活 UI。

## 验证

桥测试在本机临时起 TLS 模拟服务器，检查证书信任、Upgrade、二进制字节透传、令牌隔离和路由边界。C 客户端使用离线 PCM/协议模拟，不上传真实录音。单元测试通过不代表已经在所有小智服务端或所有 S12 板型上验收。
